# 回验执行细则

成稿后逐条执行六条回验，产出核对报告。**存在待确认项时不得声称完成。**

## 1. 声明溯源

- 逐条特性/能力描述，确认能指到来源（文件+位置 或 文档路径）。
- 指不到的：删除，或经用户确认后标注"用户口述（待确认）"。
- 成熟度、限制、License 名称、对比声明等事实项同样核对。

## 2. 命令静态核对

- 逐条安装/运行命令与仓库事实对照：package.json scripts、pyproject.toml、Cargo.toml、Makefile、docker-compose.yml、CI 配置。
- **不实际执行命令**（避免污染用户环境），除非用户明确要求实跑。
- 分平台命令逐平台核对；`curl | bash` 类安装确认"先审脚本"提示是否与仓库事实一致。
- 对不上的命令：修正或删除；无法确认的进"待确认"。

## 3. 链接与媒体核对

- 本地链接（LICENSE、CONTRIBUTING.md、docs/xxx、assets/xxx）：逐一确认文件真实存在；折叠内容里的链接同样核对。
- 文内锚点：目标标题真实存在；标题改动后同步更新全部引用。
- 外部链接：核对一致性（git remote、manifest 包名、组织名），不做全量 HTTP 请求；可疑的（拼写、占位符、example.com 残留）进"待确认"。
- 图片与媒体：本地图必须存在；外链图核实指向与说明一致；alt 非空且与图内容相符；GIF / 大图提示仓库体积风险。
- badge：白名单之外、指向失效服务、自证或假数据、点击目标与 alt 不符——列出并进"待确认"或删除。

## 4. 数字核对

- 版本号：来自 manifest / lockfile。
- 下载量 / star / benchmark 数字：必须有真实来源；禁止估算、约数、占位符。
- badge 的 alt 与链接目标一致。

## 5. 读者三路径走查

站在读者立场静态走一遍（不实际运行），结论写进报告开头：

- **3 秒**：只读前 40 行，能否说出"是什么、给谁、凭什么选它"。
- **60 秒**：把 Quick Start 当清单逐步核对——前置完整、命令可复制、预期输出真实、失败有提示；任何一步会卡住即记问题。
- **5 分钟**：对比、局限、演示、文档入口是否齐备且真实；决策所需信息是否都在。

## 6. 核对报告（收尾输出）

先给读者三路径结论（各一句："通过 / 卡点在 X"）；再按固定四段输出：

1. **已核实**：分类列出（声明 / 命令 / 链接 / 数字）
2. **待确认**：来源缺失或用户口述项，逐条列出
3. **缺失提示**：如 LICENSE / CONTRIBUTING 不存在（只提示，不创建）
4. **备份路径**：非 git 仓库覆盖原文件时给出

报告开头如实声明是否存在未核实项；有则不得声称完成。
