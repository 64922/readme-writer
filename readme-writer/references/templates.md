# README 骨架与各节规范

## 骨架总览

核心节（按序，7 个）：Hero → What/Why → Quick Start → Usage/Examples → 深入链接 → Contributing → License。

可选节（证据门控 + 用户确认）：

| 节 | 加入条件 | 写作要点 |
|----|---------|---------|
| News / Releases | 有真实 release / changelog | 只留最近 3–5 条；完整历史折叠或外链 |
| FAQ / Troubleshooting | issue 区有反复出现的真实问题 | 收录真实问题与 workaround，给排障入口 |
| Roadmap | 有真实 issue / 里程碑 / TODO | 优先链活的 issue 查询；静态清单注明更新时点 |
| Demo / Showcase | 有在线 Demo 或真实用户作品 | 只链有效入口；作品需真实且公开 |
| Architecture / How it works | 有真实架构图或讲得清的机制 | 图用真实资产或 Mermaid；机制与代码一致 |
| Ecosystem / Prior art | 有相关项目、灵感来源或衍生项目 | 标明差异；不暗示不存在的合作关系 |
| Community | 有真实社群入口（Discord / 微信群 / 论坛） | 只列有效的 |
| Citation | 有论文 / DOI | 给 BibTeX；作者与发表信息与论文一致 |
| Acknowledgements | 有资金 / 机构 / 灵感 / 第三方资产 | 含第三方许可与版权信息 |
| 语言 switcher | 仓库已有真实翻译文件 | 只链真实存在的；不创建翻译文件 |
| ToC / 导航 | README >100 行或用户要求 | 折叠式 ToC 可用；长文给"回到顶部"链接 |
| AI 工具专属 | 项目是 AI 工具 / 库 | llms.txt、MCP 等真实入口；数据上传范围明细 |
| 维护状态横幅 | 停更 / 迁移 / 更名 / 冒名风险 | 顶部醒目、指向后继；只写事实 |

铁律：任何节缺素材 → 省略或降级为一句，禁止空壳、禁止编造。

**三条读者路径**（全篇服务的目标）：3 秒内首屏说清"是什么、给谁、凭什么"；60 秒内按 Quick Start 跑通并知道成功的样子；5 分钟内凭对比、局限、演示与链接做出采用决策。

## 核心节

### 1. Hero（首屏）

任务：前 40 行完成 3 秒定位。组成：项目名（H1）+ 一句话定位（给谁、解决什么）+ 仅真实 badge + 真实演示（如有）。

- 一句话定位 ≤2 行，不堆形容词。
- **演示优先**：仓库有真实截图 / GIF / 在线 Demo，就放在 Hero 或紧随其后；没有就不硬凑。
- 图片：只用仓库真实存在的资产；alt 必填，且写成完整的功能 / 平台 / 许可摘要句（示例：Terminal.Gui 把 hero 动图的 alt 写成一句卖点清单）；深浅双版可用 `<picture>`；GIF 提醒仓库体积风险，优先静态图。
- 顶部状态位（有则置于最前、醒目）：弃用 / 迁移横幅、维护线说明（如 v1 维护 vs v2 当前）、防冒名声明——只写事实。
- 顶部快捷入口行：网站 / 文档 / Demo / Docker 等真实入口（只列存在的）。
- 居中 HTML 最小集模板：

````html
<div align="center">
  <img src="./assets/logo.png" alt="项目名" width="120">
  <h1>项目名</h1>
  <p>一句话定位：给谁、解决什么问题。</p>
  <p>
    <a href="https://example.com"><img src="https://img.shields.io/..." alt="说明"></a>
  </p>
</div>
````

- HTML 只用 GitHub 稳定渲染的最小集：`<div align="center">`、`<img width>`、`<picture>`、`<details>/<summary>`、`<br>`、`<hr>`。渐变、复杂内联 style、装饰性花活不用——跨渲染器易碎。
- **Badge 白名单**（只允许四类）：
  1. CI / 构建状态
  2. 包版本 / 下载量
  3. License
  4. 文档 / 社区入口

  **禁止**：求 star / 赞助 / affiliate、自证状态（"maintained: yes"）、社交与趋势图标、已停服服务（如 Travis）；禁止假 badge 与自指 badge。建议 ≤6 枚（硬上限 ≤2 行、≤8 个）；枚数多时按语义分组放进带标签的表格，而非徽章墙。每个必须点击指向真实目标。
- Emoji：章节标题做视觉锚点，每节 ≤1 个、全篇风格统一；正文克制。
- 语言 switcher：仅当仓库已有真实翻译文件（README-zh.md 等）才加，只链真实存在的；不创建翻译文件。

### 2. What / Why

- 1 段说明（是什么、给谁、解决什么）+ 要点式特性列表（每条能指到代码或文档；能给 Demo 链接就给）。
- **对比定位**：一句话讲清差异，或给对比表（本品 vs 替代品），不贬低、有据。
- Problem → Solution 结构（三行卡片或表）适合讲清动机。
- 诚实边界：成熟度（alpha/beta/稳定）、已知限制、不适合谁（一句）、未验证事项显式标注——只写事实。
- 停更 / 归档项目：顶部状态横幅 + 一行说明，不煽情。

### 3. Quick Start（README 最高价值区）

四件套缺一不可：

1. 前置条件（运行时版本、系统依赖、账号/Key）
2. 安装（命令可直接复制执行；多路径时给决策提示："如果你是 X，走 Y"，主路径置顶，其余可折叠）
3. 最小可用示例
4. 预期输出（终端横幅 / `--help` 输出 / 截图，至少一种真实证据，让读者知道自己成功了没）

- 命令必须与仓库事实对得上（manifest scripts / Makefile / docker-compose / CI）；分平台命令逐平台标注。
- 安装路径 ≤3（如 pip / 源码 / Docker）；长参数表、配置项表外链 docs。
- `curl | bash` 类安装：如实提示先审脚本（仓库有该建议时保留）。
- 常见坑：从真实 issue 提炼 1–3 条（可折叠），禁止想象。
- 需要 API Key 的：给出获取入口；示例里用占位符，禁止出现真实密钥。

### 4. Usage / Examples

- 1–2 个真实用例，标题写需求场景（如"用自然语言查询你的文档"），不写"Example 1"。
- 能配 Demo 链接或短录屏就配；折叠块可把预览图放进 `<summary>`，展开前先看到效果。
- 更长内容用 `<details>` 折叠或链接 docs；示例代码必须对应仓库里的真实 API/命令（静态核对）。

### 5. 深入链接

- README 是路由器，不是文档仓库：docs / API 参考 / 论文 / 相关项目；只链真实存在的目标，不复制 docs 内容。
- 仓库没有 docs 时写清深入内容的实际位置（代码注释、Wiki），不虚构。

### 6. Contributing

- 有 CONTRIBUTING.md → 链接它；没有 → 一句话（欢迎 issue/PR）或省略。
- 不编造贡献流程细节。

### 7. License

- 有 LICENSE 才写，名称与 LICENSE 文件一致，并链接该文件。
- 没有则省略（收尾报告提示缺失，不代建）。

## 表达工具选择

- **表格**用于：安装路径对比、参数（类型 / 默认 / 必填）、兼容矩阵、安全 / 权限边界、对比替代品、下载清单、badge 语义分组。
- **`<details>`** 用于：changelog、ToC、长 API 清单、长示例、视频、次级安装路径、FAQ 展开；`<summary>` 一行写清里面是什么，有真实预览图就放进去。
- **锚点**：>100 行给 ToC；长文关键节给"回到顶部"；标题文案发布后尽量不动（改标题会断旧链接）。
- **未验证内容**：显式标注（"待验证 / under verification"）或删除，不混入正文装成事实。
- **活资产**（issue 自动查询、自动生成图、动态 badge）：维护成本高，仅当用户确认会维护时才用。

## 篇幅预算

- 首屏（Hero + 定位 / 演示）≤40 行。
- 正文（不含折叠内容）150–400 行；>500 行触发逐节审查："这内容属于 README 还是 docs？"
- 超长时优先折叠，其次外链既有 docs；仓库没有 docs/ 且用户保持单文件 → 允许超标，但收尾报告标注"建议迁移到 docs/"。
- 只链接既有 docs；绝不新建 docs 文件。

## 写作风格

- 语气：库 / 工具类克制精确；产品类可适度热情；禁无实据的空洞形容词（powerful、revolutionary、state-of-the-art），禁自夸与求 star。
- 赞助 / 支持 / 感谢节放文末（Contributing / License 附近），不得出现在首屏与 Quick Start 之前。
- 可扫读：代码块优先于段落；段落 ≤3 行；小标题分层；表格只在结构化信息时用。
- 标题统一用 ATX `#`；图片 / badge 混排时避免 setext（`===`）把上一行误解析成标题。
- 无障碍：所有图片 alt 非空且描述真实用途；不只用颜色传达状态。
- 术语保留英文原词（token、embedding、CLI），正文不中英混排。
- 草稿阶段随手记录每条命令/数字/链接的来源，供阶段 5 回验。
- 反例库见 `samples.md`（badge 墙、空章节、死链接、超长不折叠等）。
